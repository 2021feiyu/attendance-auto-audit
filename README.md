# 考勤自动审核（attendance-auto-audit）

**把"几十张考勤表 × 十几条规则"的人工核对，变成一次跑批。**

企业里月末考勤核对通常是这样的：十几个分公司 / 工作室各交一张表，每张几百到几千行，规则十几条（迟到、早退、缺卡、加班时长、请假类型与额度……）。人工逐行对，一天看不完，还容易漏。

这套脚本把流程拆成四步，交给 LLM 做"逐行比对规则"这件苦力活：

```
原始考勤表 → 批次拆分 → 字段索引 → 并发审核 → 结果汇总（Excel + TXT）
```

---

## 工作流程

| 步骤 | 脚本 | 做什么 |
|---|---|---|
| 1. 拆分 | `考勤数据批次拆分.py` | 按行数把大表切成小批，避免单次请求超上下文 |
| 2. 索引 | `generate_field_index.py` | 把表头列名映射成固定坐标，让提示词里的"第 N 列"永远指向同一个字段 |
| 3. 审核 | `考勤自动审核.py` | 并发调用模型，逐批比对规则，强制返回固定表头 CSV |
| 4. 汇总 | 同上（内置） | 合并各批结果，输出 Excel + TXT |

### 几个关键设计

- **固定表头约束**：系统提示词要求模型只输出 `序号,考勤异常汇总,非考勤内容` 三列 CSV，禁止解释性文字。解析端因此不需要处理自由文本。
- **低温度**：`TEMPERATURE = 0.3`——审核要的是稳定复现，不是发挥。
- **字段索引先行**：列名一旦变化，规则就错位。索引文件把"实际表头"和"规则里的字段"解耦。
- **断点续传 + 重试**：`CONCURRENT_BATCHES = 5`、`RETRY_TIMES = 2`，中途失败不用从头跑。
- **结果可追溯**：每批结果单独落盘，汇总表保留批次号，出问题能定位到原始行。

## 快速开始

```bash
pip install pandas openpyxl requests

cp .env.example .env      # 填入 DOUBAO_API_KEY
python 考勤数据批次拆分.py   # 1) 拆批
python generate_field_index.py  # 2) 生成字段索引
python 考勤自动审核.py       # 3) 审核 + 汇总
```

### 环境变量

| 变量 | 说明 |
|---|---|
| `DOUBAO_API_KEY` | 火山引擎 Ark（豆包）API Key，**唯一必填项** |

模型与端点写在脚本顶部：`MODEL_NAME`、`API_BASE_URL`、`TEMPERATURE`、`API_TIMEOUT`、`MAX_TOKENS`。换模型只要改这两行。

---

## 输入格式

- Excel（`.xlsx`），首行为表头，一行一条考勤记录
- 规则以纯文本给出（见仓库内规则文本的组织方式），一行一条，能被模型逐条对上

---

## 注意

- **数据会离开本机**：审核需要把考勤内容发给模型服务商。含真实姓名、工号、身份证号的表，请先脱敏或改用内网模型。
- 审核结果是"疑似异常清单"，**不是最终结论**——输出的是待人工复核项，不是处罚依据。
- 不同公司的考勤规则差异很大，`SYSTEM_PROMPT` 与规则文本需要按自己的制度改写。
